Conduit API

The v0 API is a canonical request envelope plus a local control surface. Clipboard-origin execution must include schema, source metadata, permissions, session ID, nonce, and stable action IDs.

```conduit
{
  "schema": "conduit.request.v1",
  "source": { "kind": "clipboard", "trust": "untrusted" },
  "permissions": [
    { "kind": "filesystem", "scope": "project", "access": "read" }
  ],
  "sessionId": "session_...",
  "nonce": "nonce_...",
  "actions": [
    {
      "id": "list_project",
      "tool": "file.list",
      "args": { "path": "." }
    }
  ]
}
```

Envelope parser

Compliance mode accepts raw JSON or a single copied fenced conduit or conduit-json block. Pages and agents may explain the block nearby, but the clipboard buffer itself cannot include that prose.

Local app API

GET /api/status, GET /api/sessions, POST /api/sessions, POST /api/clipboard/check, approvals, and run result endpoints back the control app. It listens on 127.0.0.1 only and refuses cross-origin writes.

Result format

Conduit-native request execution returns CONDUIT_RESULTS_JSON. Agent-loop compatibility can still use legacy tool result blocks.

Duplicate JSON keys, comments, trailing commas, missing source metadata, and missing permission declarations are rejected for clipboard execution.
